# 第四节课实践：给成绩导出文件增加 HMAC

这次把课件第 13 个内容页的示例加入了正在使用的 NotesApp：导出成绩时附上 HMAC，老师可以上传文件检查是否被改动。课件没有明确把它列为必须提交的课后作业；这里保存的是本次主动实现与实测。

## 直接体验

1. 打开 [NotesApp](http://127.0.0.1:8080)。如果尚未运行，双击 `NoteApp/Start-NoteApp.cmd`。
2. 用课程教师账号登录：`prof.turing`，密码 `teach123`。
3. 老师页顶部 **Export all grades** 下载全部成绩；班级旁的 **export CSV** 下载该班成绩。
4. 点击 **Verify an exported CSV**，选择刚下载的原文件，再点 **Verify file**。
5. 正常情况显示 **Verification passed**，即校验通过。

已经准备好三份可以直接上传的演示文件：

| 文件 | 预期结果 | 原因 |
| --- | --- | --- |
| [grades_original.csv](results/grades_original.csv) | 通过 | 服务器导出的原始数据和 HMAC |
| [grades_tampered.csv](results/grades_tampered.csv) | 失败 | 第一个成绩增加 1 分，但保留原 HMAC |
| [grades_unsigned.csv](results/grades_unsigned.csv) | 失败 | 删除了末尾的 HMAC |

**演示只修改下载文件，不修改数据库里的真实课程记录。** 校验入口也不负责导入成绩，它只检查文件。

这三份文件对应本机的私有密钥。提交包不带密钥，换一台电脑使用新密钥时，应从那台电脑的应用重新导出文件；旧样例无法在新密钥下通过，这是正常保护行为。如果只想演示原理，可在本目录运行 `python demo_hmac.py`，它临时生成内存密钥，演示原件通过和改分失败，不需要数据库，也不保存密钥。

## 文件里多了什么

原来的四列仍然是：

```text
student,class,grade,comment
```

文件最后增加一行，格式如下：

```text
# HMAC: v1:sha256:这里是64个十六进制字符
```

这一行是校验元数据，不是学生成绩。文件里的姓名、成绩和评语仍然能读到，**HMAC 不会把 CSV 加密**。数据库中的评语继续使用上一节课做的 AES-GCM 加密；导出时应用先解密评语，再对完整 CSV 数据计算 HMAC。

普通 CSV 阅读程序不一定认识这行元数据，可能把它当成一条不完整记录。程序处理时，应先验证整个文件，再解析验证函数返回的纯 CSV 数据部分。本次已同步更新原有测试，避免把末尾校验行算成第 61 个学生。

## 为什么改完文件不能重新算一个正确 HMAC

普通哈希只需要文件，人人可以重新计算。HMAC 还需要一把只有服务器持有的秘密密钥：

```text
导出：CSV 原始字节 + 服务器的 HMAC 密钥 → 校验码
验证：收到的 CSV 字节 + 同一把密钥 → 重新计算并比较
```

攻击者知道算法和旧校验码，但没有服务器密钥，就难以给修改后的文件生成有效新校验码。这里使用 Python 标准库的 `hmac`，底层摘要算法为 SHA-256，不自行设计密码算法。

HMAC 需要持钥方验证；它不是“任何人拿公钥就能验证”的数字签名。它也不能判断老师最初是不是写错了成绩。

## 本次具体保护哪些内容

程序验证的是 CSV 数据的**原始字节**，包括四列标题、全部记录、标点、引号、空格、编码与换行。最后附加的 HMAC 行不参与自身计算。

因此下面这些变化都会导致失败：

- 成绩、姓名或评语被修改；
- 文件被截断或追加新内容；
- 校验码被修改、删除或格式损坏；
- 使用另一把密钥的服务器生成文件；
- 换行从 CRLF 改成 LF，或编辑器保存时改变编码。

**用 Excel 打开后重新保存，即使屏幕上看着没变，也可能验证失败。** 应保留最初下载的文件作为原件。单纯改文件名不会改变文件内容，不影响验证。

旧版本导出的无 HMAC 文件不会自动升级，应该重新从应用导出。以前导出的旧成绩只要文件未变、原密钥还在，仍可能通过，所以校验通过不证明它是最新版本。

## 密钥保存在哪里

新密钥在课程根目录的 `.secrets/notesapp-export-hmac.key`，为独立随机生成的 32 字节。它不同于评语加密密钥、登录密钥和 JWT 密钥。Docker 通过只读 secret 挂载给应用，项目源码和提交包里不包含它。

`Initialize-ExportKey.ps1` 只在首次初始化时创建密钥。以后启动继续使用原密钥；已经初始化却丢失密钥时，脚本要求恢复，不会悄悄生成新密钥使旧文件失效。缺失密钥或密钥长度不正确时，应用拒绝启动。

如果复制项目到新电脑：使用新密钥可以生成新的演示文件，但不能验证原电脑用旧密钥生成的文件。恢复原数据库和历史导出时，需要同时恢复对应的原始密钥。不要把密钥发给同学或放进 GitHub。

## 代码从哪里看

| 文件 | 先看什么 |
| --- | --- |
| [export_hmac.py](../../web/export_hmac.py) | `sign` 附加校验行；`verify` 验证成功后返回原始数据 |
| [app.py](../../web/app.py) | `/export.csv` 调用 HMAC；`/verify-export` 处理上传 |
| [verify_export.html](../../web/templates/verify_export.html) | 上传表单以及通过 / 失败提示 |
| [Initialize-ExportKey.ps1](../../Initialize-ExportKey.ps1) | 创建并保留独立密钥 |
| [test_export_hmac.py](../../tests/test_export_hmac.py) | 改一个字节、换密钥、缺失校验码等测试 |
| [test_export_routes.py](../../tests/test_export_routes.py) | 老师权限、文件上传、空班级和数据库不变的测试 |

`hmac.compare_digest` 用于比较校验码，避免使用遇到不同字符就提前退出的普通比较方式。文件有明确版本标记，认证数据还带 `notesapp:grades-export:v1` 的用途标识，避免与其他用途混用。

新入口只接受老师会话，并检查表单 CSRF 令牌；匿名用户和学生不能使用。上传请求最多 8 MiB。文件不会被当作程序执行、放进成绩数据库，或直接显示成 HTML。

## 实测怎么看

- 全部导出为 **60 条成绩**；四个班级分别 **16、10、23、11 条**，均与实际数据库一致。
- 原件通过；改成绩、去掉 HMAC、追加数据、使用错误密钥均失败。
- 重启 Web 容器后，之前下载的原件仍通过，说明没有每次启动换密钥。
- 真正的无头 Chrome 浏览器走过登录、下载、上传原件、上传篡改件的过程，并检查手机宽度的表单。
- 35 个用户、4 门课程、60 条选课、60 条成绩以及加密状态表的内容摘要，与修改功能前一致；评语密文也没有重写。
- 自动检查和覆盖率以 [verification.txt](results/verification.txt) 为准；新 HMAC 模块的语句和分支覆盖率均为 100%，并不代表整个教学应用没有漏洞。

## 运行自动检查

在已安装 `requirements-dev.txt` 的 Python 环境中，从仓库根目录执行：

```powershell
python -m pytest -q --cov=export_hmac --cov=comment_crypto --cov=comment_migration --cov-branch --cov-report=term-missing --cov-fail-under=95
```

Docker 数据库需要运行。测试会新建名称带随机值的临时数据库，完成后只删除自己的测试库。不要把应用数据库拿来重新初始化。

如需再次核对已经运行的应用，在仓库根目录执行：

```powershell
python docs/session04/verify_live.py verify
```

`prepare` 只用于第一次记录修改前的基线，本次已经完成，不需要重复。可选浏览器检查运行 `verify_browser.py`，需另装 Playwright，使用本机 Chrome 或 Edge；它不是应用正常运行的依赖。

## 自测

1. 为什么学生能看见文件末尾的 HMAC，却不能轻易伪造修改后的文件？
2. 校验通过，能否证明老师给出的分数一定正确、文件一定是最新的？
3. 文件里有 HMAC，成绩和评语是否还可被别人读到？
4. 为什么仅改换行也会失败，而改文件名不会失败？
5. 如果把服务器密钥发给所有人，会失去什么保护？

答案：1. 还需要服务器秘密密钥。2. 都不能，只校验被认证的数据字节。3. 可以，HMAC 不加密正文。4. 换行属于文件字节，文件名不在认证数据内。5. 所有人都能给改过的文件生成有效 HMAC，无法再用它区分服务器与其他持钥者。
