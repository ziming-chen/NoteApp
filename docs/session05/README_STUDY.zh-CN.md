## 第 1 页：Lab 1 的发现与修复

**实验范围：** 本机 NotesApp、回环抓包，以及老师提供的模拟账号。没有测试其他人的网站或数据库。

**发现 1：HTTP 会暴露登录凭据。** HTTP 的 POST /login 请求中，能直接读到 `username=alice&password=alicepw`。原抓包第 348 包、TCP 流 9 含该正文；第 350 包返回 HTTP 302。能截获这段未加密连接的人可能得到密码，因此严重性判断为 **High（高）**。

**修复：** 用 nginx 在 Flask 前面提供 HTTPS，关闭对外发布的 Flask 8080 端口，80 端口转到 HTTPS。

**复测：** HTTPS 抓包含 75 个包，协商为 TLS 1.3，截图对应 TCP 流 6。不提供 TLS 会话密钥时，在所有重组 TCP 流中没有找到明文登录凭据。成功登录截图和服务器访问记录证明本次确实完成了 HTTPS 登录。HTTP 根路径和 /login 都返回 301 跳转，直接访问 8080 失败。Lab 1 没有改变数据库内容。

**发现 2：连接加密与身份可信是两个检查。** GitHub 的直接颁发者是 Sectigo Public Server Authentication CA DV E36，证书链到 Root E46；本机证书的主体和颁发者都是 localhost，链里只有它自己。Edge 提示 `NET::ERR_CERT_AUTHORITY_INVALID`。缺少的是通往浏览器信任根的证书链，不能因为加密了就自动认为服务器身份可信。

## 第 3 页：Lab 2 的两个发现与计时

真实应用原本存明文。MD5 测试文件是老师要求单独生成的六个模拟账号，不是从真实数据库导出并转成 MD5 的账号表。

**发现 1：无盐 MD5 的离线猜测成本低。** 你原来预测 6/6、10 ms；实测是公开字典 170 个候选，**4/6、0.1607 ms**。终端显示 0.161 ms，是四舍五入，原计时是 160,700 ns。

被找回的是 liwei/123456、aisha/password1、tomk/qwerty123、sofia/iloveyou；marie/mariepw、raj/Gv7#pLm2!xQ 不在这份字典中。脚本只是给候选算哈希再比较，并没有“解密 MD5”。没被这份字典匹配不等于绝对安全。

严重性判为 **High**：攻击者拿到密码表后，可在自己的机器上离线计算，不受网页登录次数限制。修复是随机盐加 Argon2id，并在正确旧密码登录后升级。

**发现 2：测量修复增加的每次成本。** 你原来预测慢约 10 倍；本机结果如下。

| 算法 | 每秒估算次数 | 每天估算次数 |
| --- | ---: | ---: |
| MD5 | 3,336,597 | 288,282,016,688 |
| Argon2id | 27.105 | 2,341,905 |

Argon2 一次新哈希 **36.893 ms**，相对 MD5 每次操作约慢 **123,097 倍**。两者在同一个 Python 3.11.17 Docker 容器计时：MD5 连算 100,000 次，再算一次 Argon2。Argon2id 使用 64 MiB 内存、时间成本 3、并行度 4、16 字节随机盐和 32 字节输出。

每天数值只是“每秒 × 86,400”，不是实际攻击了一整天。计算新哈希是老师给定的猜测成本估算方法，不是专业破解软件跑出的通用显卡速度。Argon2 提高每次成本，但 password1 这样的常见密码仍可能被找回。

## 第 4 页：迁移核验、最后状态与边界

你的预测是 alice 登录后变成哈希。实际第一次正确登录后，数据库中的 alicepw 变为 `$argon2id$v=19$m=65536,t=3,p=4$...`。之后的正确登录走哈希验证分支，不再把旧值当作明文比较。

| 核验 | 结果 |
| --- | --- |
| 迁移前输入错误密码 | 拒绝，不迁移 |
| 第一次输入正确旧密码 | 成功，alice 升级为 Argon2id |
| 迁移后输入错误密码 | 拒绝，已存哈希不变 |
| 退出再正确登录 | 成功，已存哈希不变 |
| 其他数据 | 另外 34 个用户以及所有非用户表的摘要未变 |

截图是实际登录后的页面，数据库中的哈希另有真实 SELECT 输出：[alice-storage.txt](lab2/results/alice-storage.txt)。两种证据配合使用；仅看到成绩页不能单独证明数据库已迁移。

最终 HTTPS 与 Argon2id 登录都在运行。35 个账号里只有 alice 已迁移，其他 34 个等待成功登录后逐个升级。管理端创建账号的旧行为和其他教学漏洞不在本次改造范围；用户名拼接 SQL 的缺陷按老师要求保留给之后的课。

15 项新增密码检查、75 项既有评语/HMAC 检查通过。密码辅助模块语句、分支覆盖率均 100%，不代表整个应用没有漏洞。后续五次新哈希中位数 32.051 ms；五次已有哈希验证中位数 31.058 ms。它们是不同工作量，报告分别记录。

**可选规则测试：** 在原字典后加六个“用户名 + pw”候选，结果变成 **5/6、0.1728 ms**，新找回 marie。raj 只是在这 176 个候选中未匹配。原来的 4/6 记录仍保留。

**证据来源：** Lab 1 抓包和最初 MD5 命令由你操作取得；你授权继续后，登录、性能和可选规则检查由本机自动化完成。自动化对本机自签名证书放行，不等于证书已获得公共 CA 信任。

## GitHub 仓库中的复现方法

实际生效的代码在仓库根目录的 `web/`、`tests/` 和 `nginx/`；`lab1/`、`lab2/` 是报告的原始证据与实现快照。执行[英文运行说明](README.md#run-the-submitted-application)时，要先生成自己的 TLS 证书与私钥。仓库附的 `lab1/configuration/notesapp.crt` 只是实验时观察到的公开证书，不含配套私钥，不能当作新机器现成可用的 HTTPS 身份。

**私钥为什么没上传？** 私钥用于证明服务器身份，需要保存在本机；公开证书可以附在报告里。`nginx/certs/` 的运行证书和私钥被 Git 忽略，公开的历史证书在证据目录中另存。旧启动器选择普通 HTTP，HTTPS 需使用三份 Compose 配置。

复制仓库后，可以按 [Lab 2 命令](lab2/README.md)重新运行六个模拟账号的字典测试，并把 `measure_hashes.py` 输入到 web 容器测量。历史 `run_benchmark.py` 和 `verify_live.py` 保留原课程工作区路径；在仓库布局中应使用上述入口。不要为了重拍第一次迁移就把实际账号改回明文；自动测试会在临时数据库中核验升级过程。
